# Job digest

Every weekday at ~08:00 (Argentina), GitHub Actions runs this for each person:

1. **Fetch** fresh postings from LinkedIn, Indeed, GetOnBoard and company career boards (`fetch.py`).
2. **Filter** them by title and location, and skip jobs already sent before.
3. **Score** each job 0-10 against the person's profile with Claude Haiku (`tailor.py`).
4. **Write a tailored one-page CV** (PDF) with Claude Sonnet for every job scoring 6 or more.
5. **Email** the person a digest with links, scores, reasons and the CVs attached (`email_digest.py`).
   Jobs below 4 are left out.

## Files

```
config.yaml                    shared settings for everyone (score thresholds, how far back to search...)
people/_example/               a fake person (accountant), to copy as a model
people/<name>/profile.md       PRIVATE  everything about the person (raw notes are fine)
people/<name>/searching.md     PRIVATE  what jobs they want, in plain words (only read by setup.py)
people/<name>/settings.yaml    PRIVATE  generated by setup.py: searches, filters, CV header, education
people/<name>/seen.json        public   jobs already sent, so nothing repeats
setup.py                       turns profile.md + searching.md into settings.yaml, and uploads secrets
```

The repo is **public**. Files marked PRIVATE are gitignored and never committed. GitHub gets them as
secrets (`PROFILE_<NAME>`, `SETTINGS_<NAME>`) and each run recreates them.

## Adding a new person

You need, on your PC: Python with `pip install -r requirements.txt`, Claude Code logged in (`claude`),
and the GitHub CLI logged in (`gh auth status`).

**1. The person writes two files** (Spanish or English), using `people/_example/` as the model:

- `profile.md`: contact (name, phone, email, LinkedIn), studies with dates, every job with what they
  actually did (concrete facts and numbers make better CVs), tools, languages and certifications.
  Rough notes are fine, since Claude rewrites them for each job. Nothing untrue: whatever is written here
  ends up on CVs.
- `searching.md`: a few lines on the jobs they want, the seniority, where (on-site/hybrid/remote and the
  city), and what they do **not** want (e.g. "no sales or HR").

**2. Put them in a folder** named after the person. Use a short lowercase name with no spaces or accents.
The name is visible in the public repo, so a nickname is fine.

```
people/sofi/profile.md
people/sofi/searching.md
```

**3. Generate the settings:**

```
python setup.py sofi
```

This writes `people/sofi/settings.yaml`. **Open it and check it**, especially:
- `contact` and `email_to`: the digest goes to `email_to`.
- `search_terms` / `linkedin_terms`: the searches that are run.
- `title_include` / `title_exclude`: a job title must contain an include word and no exclude word.
  Words are matched at the start of words, so `contab` matches "contable" and "contabilidad".
- `onsite_locations`: on-site jobs elsewhere are dropped. Remote jobs always pass.
- `education` / `languages`: printed exactly like this on every CV.

Edit anything by hand if needed. Running `setup.py sofi` again regenerates it from scratch.

**4. Upload the private files to GitHub:**

```
python setup.py sofi --upload
```

**5. Add the name to the workflow** in `.github/workflows/digest.yml`:

```yaml
        person: [andre, sofi]
```

Then commit and push:

```
git add .github/workflows/digest.yml
git commit -m "Add sofi"
git push
```

**6. Test it now** instead of waiting for tomorrow:

```
gh workflow run digest.yml
```

Watch it under the repo's **Actions** tab (~10-20 min per person). The email should arrive at `email_to`.
Check spam the first time.

## Changing someone's info or searches later

- Edit `people/<name>/profile.md` and/or `people/<name>/settings.yaml`, then run
  `python setup.py <name> --upload`. Without the upload, GitHub keeps using the old version.
- Only run `python setup.py <name>` (without `--upload`) if you want to regenerate `settings.yaml` from
  `searching.md`. It **overwrites** hand edits. `andre` has no `searching.md` on purpose: edit his
  `settings.yaml` directly.
- **Company career boards:** add company names under `boards:` in the person's `settings.yaml`. The name
  comes from the company's careers URL: `boards.greenhouse.io/<name>`, `jobs.lever.co/<name>` or
  `jobs.ashbyhq.com/<name>`.

## Running it on your PC (optional)

```
python fetch.py sofi                 # -> people/sofi/new_jobs.json
python tailor.py sofi --limit 3      # -> out/sofi/<date>/digest.html + CV PDFs
```

`tailor.py` marks the jobs it scores as seen. Don't commit a local `seen.json` unless you mean to.

## One-time account setup (already done)

The repo secrets, shared by everyone:
- `CLAUDE_CODE_OAUTH_TOKEN`: from `claude setup-token`. Everyone's runs use this Claude account.
  The token lasts about a year.
- `GMAIL_USER` / `GMAIL_APP_PASSWORD`: the Gmail account that sends all digests, and an app password from
  https://myaccount.google.com/apppasswords (16 letters, no spaces).

## When something breaks

GitHub emails the repo owner when a run fails. Open the run in the **Actions** tab and look at the red step.

| Symptom | Likely cause / fix |
|---|---|
| `tailor.py` step fails with an auth error | Claude token expired: run `claude setup-token` in a normal terminal, then `gh secret set CLAUDE_CODE_OAUTH_TOKEN` |
| `email_digest.py` fails to log in | Gmail password changed: make a new app password, then `gh secret set GMAIL_APP_PASSWORD` |
| "Write private files" makes empty files / settings error | That person's secrets are missing: `python setup.py <name> --upload` |
| Digest is empty or thin for days | LinkedIn blocks some searches (`429` in the log). Add more `search_terms`, or companies under `boards:` |
| Wrong kinds of jobs | Tighten `title_exclude` / `title_include` in that person's `settings.yaml`, then upload |
| Scheduled runs stopped | GitHub pauses schedules after 60 days without repo activity: re-enable the workflow in the Actions tab |
